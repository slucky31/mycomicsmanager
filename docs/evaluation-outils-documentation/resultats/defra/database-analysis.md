# Analyse de la base de données

## Remarques préliminaires

- Il n'existe **ni `.sqlproj`, ni procédure stockée, ni fonction, ni vue, ni trigger** dans le code source. Aucun fichier `.vb` n'a été trouvé, et aucun SQL inline de type `CommandText` n'existe dans le code C#.
- Le SGBD n'est **pas SQL Server mais PostgreSQL** (types `uuid`, `jsonb`, `text[]`, `xid`, `timestamp with time zone`, `GENERATED BY DEFAULT AS IDENTITY`, index GIN, extension `pg_trgm`). La persistance est assurée par EF Core (migrations C#), avec un script SQL idempotent généré : `src/database/mycomics-schema.sql`.
- Le script `mycomics-schema.sql` ne contient **pas** la migration `20260321120000_AddTrigramIndexesForBooksSearch` (index trigrammes) ; celle-ci n'est visible que dans le code C# des migrations. Le script est donc incomplet par rapport à l'historique réel des migrations.
- Le script contient aussi la migration `20261003171656_FeedImportDecisionEventIdNotGenerated`, qui ne génère aucune instruction DDL (changement de modèle uniquement).
- Le schéma ci-dessous est l'état **final** obtenu en appliquant toutes les migrations dans l'ordre.
- Les longueurs maximales proviennent du script SQL ; les constantes (`BookConstants`, `ImportJobConstants`, `FeedImportConstants`, `LibraryConstants`) n'ont pas été lues, seules leurs valeurs finales dans le script SQL font foi.
